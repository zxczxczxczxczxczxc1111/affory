ЕСЛИ ПОСЛЕ ОТКЛЮЧЕНИЯ AFFORY НЕ ВЕРНУЛАСЬ СЕТЬ
===============================================

Открой командную строку от имени администратора.

1. Отключи туннель и его защиту:

    "{{КАТАЛОГ}}\affory-cli.exe" disconnect
    "{{КАТАЛОГ}}\affory-cli.exe" killswitch off

2. Если служба не отвечает, останови только Affory и сними её запрет:

    "{{КАТАЛОГ}}\affory-svc.exe" prepare-install

Эта команда останавливает AfforySvc и снимает запрет режима «весь трафик».
Чужие VPN не завершаются. Службу после этого можно запустить командой
sc start AfforySvc.

Запрет стоит фильтрами Windows (их имена начинаются с «Affory:») и
переживает перезагрузку: так задумано, иначе режим не защищал бы при старте
Windows. Поэтому перезагрузка сеть не вернёт, вернёт команда выше.

3. Если файлов Affory на диске нет, поставь Affory заново тем же
установщиком: перед установкой он сам снимает запрет.

ЗАМОК ВЕРСИИ 1.9.4 И РАНЬШЕ
--------------------------

Эти версии запирали машину политикой брандмауэра Windows. Если в файле
C:\ProgramData\Affory\firewall-do-affory.json есть строки "profili", после
обновления программы команда из пункта 2 снимает и его. Без файлов Affory
снимай руками.

Сначала останови AfforySvc:

    sc stop AfforySvc

Открой firewall-do-affory.json в Блокноте. Для каждого профиля domain,
private и public верни ЕГО значение politika. Например, только если в файле
у private записано BlockInbound,AllowOutbound:

    netsh advfirewall set privateprofile firewallpolicy blockinbound,allowoutbound

Если у этого профиля vklyuchen было false, верни его выключенное состояние:

    netsh advfirewall set privateprofile state off

Не меняй политики всех профилей одним значением. Если файл повреждён, открой
рядом его прежнюю версию firewall-do-affory.json.bak. Если нет ни того, ни
другого, исходные настройки неизвестны: не сбрасывай чужую защиту наугад.

После возврата политик сними только правила Affory:

{{ПРАВИЛА}}

Не завершай все процессы sing-box.exe: этот файл используют другие VPN.
Если сеть не вернулась, сохрани файл отката и журнал
C:\ProgramData\Affory\log\sluzhba.log для разбора причины.
